# OCR 评测说明

> 负责人：OCR 与工程。本文给出评测口径、样本说明与运行方式，真实结果在配置视觉模型后填入第 5 节。

## 1. 目标

回答三个问题：

1. 视觉模型在**合成小票**上的字段准确率是多少；
2. 哪类字段最容易错（金额 / 商户 / 日期），错在什么形态；
3. 识别失败时应用是否**优雅降级**（不 500、有可读提示）。

## 2. 样本

- 目录：`backend/samples/receipts/`，共 10 张合成小票 + `ground_truth.csv`；
- 生成脚本：`scripts/make_receipt_samples.py`（固定随机种子 `20261125`，可复现）；
- 版式：两种（商户小票 / 电子发票），交替生成；
- 扰动：整图随机旋转 ±1.5°，模拟拍照倾斜；
- 标注字段：`image_id, merchant, amount, occurred_at`。

```bash
pip install pillow
python scripts/make_receipt_samples.py          # 重新生成
python scripts/make_receipt_samples.py --count 20
```

## 3. 指标口径

| 字段 | 判定规则 |
| --- | --- |
| 金额 | 与标注相差 ≤ `0.01` 元 |
| 商户 | 双向包含即算对（`沙县小吃` ⊂ `沙县小吃(万达店)`） |
| 日期 | 与标注日期完全相等 |
| 三项全对 | 金额、商户、日期同时正确 |

指标偏低时优先看“金额错”还是“日期错”，两者的修复手段不同（见第 6 节）。

## 4. 运行

```bash
# 需要 .env 中已配置 VISION_API_KEY / VISION_MODEL
python scripts/eval_ocr.py
python scripts/eval_ocr.py --limit 5          # 先小样本试跑
python scripts/eval_ocr.py --tolerance 0.5    # 放宽金额误差
```

脚本输出逐张对比表和四项汇总；未配置视觉模型时直接退出，不产生费用。

## 6. 常见失败形态与处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 金额识别成 0 或 null | 小票金额字体小、或模型把“合计”和“单价”混淆 | Prompt 中强调“取最终合计金额”；必要时对图片做 2 倍放大 |
| 日期识别为 null | 小票只有“开票日期”或格式为 `2026年11月8日` | 已在 `_parse_date` 支持多种格式；仍失败则让用户补充日期（走澄清） |
| 商户带出地址/门店号 | 模型把整行当作商户 | 保留包含关系判定；前端展示截断，必要时 Prompt 加“只取品牌名” |
| 模型返回解释文字 | 未遵守“只输出 JSON” | 服务端已做 `json` 代码块与 `{...}` 提取 + 一次重试 |
| 接口 429 / 超时 | 免费额度限流 | 服务端重试 1 次并转可读提示；演示时提前预热 |

## 7. 成本控制

- 开发阶段只跑 5 张以内，确认 Prompt 稳定后再跑全量；
- 图片建议长边压到 1024 以内（后续可在 `_build_messages` 增加压缩）；
- `glm-4v-flash` 有免费档，`qwen-vl-plus` 有新用户额度，整轮评测通常不超过几元；
- 评测脚本不会自动重试整轮，避免额度被意外消耗。
