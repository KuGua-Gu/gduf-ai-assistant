# 答辩 PPT：Agent 板块大纲与演示脚本

面向 2026 GDUF 人工智能工作室二轮考核答辩，Agent 部分共 4 页，配套 3 分钟现场演示。

## 第 1 页：Agent 能做什么，怎么搭起来的

**标题**：从一句话到一本账：Agent 的定位与架构

**要点**：

- 两个入口：自然语言（「午饭 25」）与小票截图（`image_id` → OCR），统一落到「记账 / 查账 / 预算 / 消费分析」。
- 四层结构：FastAPI 接口 → Orchestrator 编排 → ToolRegistry 工具层 → TransactionService / SQLite；Agent 不直接写 SQL。
- 两个旁挂模块：MemoryStore 负责多轮记忆（SQLite，最近 8 条 + 摘要），Safety 在进入模型前拦截越界请求。
- 模型层走 OpenAI 兼容协议，DeepSeek / 智谱 / 通义只改环境变量；未配置 Key 自动降级为离线规则模式，保证离线可演示。

**建议配图**：`docs/agent-design.md` 第 1 节的架构图；右侧放一段 `app/api/deps.py` 的装配代码，突出「业务层未就绪时降级到桩」。

## 第 2 页：一次记账的完整链路

**标题**：模型起草，用户签字：两阶段记账

**要点**：

- 消息进入后先做越界检测，再组装「日期 + 类别 + 工具规则」的 system prompt，连同最近 8 条上下文调用模型。
- 模型返回 `create_transactions` 工具调用，工具层用 Pydantic 校验参数、归一化类别，一条消息多笔消费放进同一数组。
- 写操作（新增 / 修改 / 删除）不落库，只生成 `PendingAction` 确认卡片；用户点击确认后 `/api/chat/confirm` 才真正执行。
- 卡片展示金额、类别、日期、备注与来源；AA 只记用户实际支付金额，背景写入备注，不按人数相除。
- 字段不全时不猜：按金额 → 类别 → 日期逐项追问，同一字段超过两轮给出固定引导并放弃草稿。

**建议配图**：一张时序图（前端 → `/api/chat` → Orchestrator → LLM → ToolRegistry → confirm）；配一张确认卡片的截图或 `pending_actions` JSON 片段。

**可放代码**：

```python
# app/agent/tools.py：写操作转待确认动作
if spec.write_action == "create":
    actions.append(PendingAction(action="create", draft=draft))
```

## 第 3 页：让模型靠得住

**标题**：Prompt、兜底与记忆的三道保险

**要点**：

- **日期注入**：system prompt 写入「今天 2026年11月17日，星期二，Asia/Shanghai」，相对时间必须换算，避免模型沿用训练日期。
- **工具优先 + 禁止编造**：金额、统计、排名必须先查工具；缺字段先追问；写操作只能说「已生成确认卡片」，不许说「已记账」。
- **四类兜底**：模型不可用 → 重试后返回可读话术；JSON 解析失败 → 修复提示重试一次；工具异常 → 转 `ok=false` 回填模型；上下文超长 → 提示开新会话。
- **多轮记忆**：最近 8 条原文 + 超过 16 条自动压缩的摘要，追问草稿存 `state_json`，确认 / 取消 / 换话题后清空。
- **安全边界**：正则命中套现、伪造流水、规避额度、代借贷款等表达时直接拒绝，不调用模型与写库工具。

**建议配图**：兜底四象限表格；右侧放 `prompts.py` 里「工具使用规则」与「写操作规则」的原文片段，体现约束是写进 Prompt 的而不是口头约定。

## 第 4 页：评测结果与边界

**标题**：30 条用例、双模式评测，能力边界心里有数

**要点**：

- 评测集 30 条：记账 10、查账 7、预算 4、澄清 4、闲聊 2、越界 3，覆盖相对日期、AA、多笔、缺字段与高风险请求。
- 断言不只看意图，还核对实际工具名、金额 / 类别 / 日期 / 备注 / 条数，以及澄清场景缺失字段确实为 `null`。
- 离线 `--mock-llm`：53 passed、2 skipped，不联网、不写生产库，可反复复现。
- 真实模型 `--live`：逐条调用并生成 `tests/live_report.md`，按意图一致率统计，阈值 50%；当前 glm-4.6v 实测 30/30（100%）。
- 已知局限：规则模式依赖关键词、类别词表覆盖有限、记忆无向量检索、单例 + `session_id` 无多用户隔离；业务 SQLite、前端、真实 OCR、Docker 待成员 2/3/4 补齐。

**建议配图**：用例分组柱状图 / 饼图；测试输出截图「53 passed, 2 skipped」；live 报告通过率表格。

### 30 条评测集说明

| 分组 | 条数 | 覆盖点 | 用例编号 |
| --- | --- | --- | --- |
| 记账 | 10 | 基础句、相对日期、AA、多笔、类别推断、固定日期 | `record-01` ~ `record-10` |
| 查账 | 7 | 本月/上月/本周/近 7 天/今年、分类汇总、明细 | `query-01` ~ `query-07` |
| 预算 | 4 | 类别预算、总额预算、余额查询、超支检查 | `budget-01` ~ `budget-04` |
| 澄清 | 4 | 缺金额、模糊金额、缺类别、有场景无金额 | `clarify-01` ~ `clarify-04` |
| 闲聊 | 2 | 问候、能力介绍 | `chat-01`、`chat-02` |
| 越界 | 3 | 规避额度、伪造流水、贷款口子 | `refuse-01` ~ `refuse-03` |

- 不只断言意图：还核对实际工具名、金额 / 类别 / 日期偏移 / 备注 / 条数；澄清场景要求缺失字段为 `null`。
- 离线：`pytest tests/test_agent.py -q --mock-llm`；真实模型：`pytest tests/test_agent.py -q --live`（需 Key，生成 `tests/live_report.md`）。
- 跨成员契约另由 `tests/test_contract.py` 覆盖；成员 2 的 `SqliteTransactionService` 交付后，真实实现用例会自动从 skip 转为执行。

## 演示数据（可选，推荐）

在空账本上运行一次，生成可复现的答辩数据：

```bash
python scripts/demo_seed.py
# 后端不是 127.0.0.1:8000 时：
python scripts/demo_seed.py --base http://127.0.0.1:8001
```

写入三笔（均为今天）：午饭 25（餐饮）、打车 32（交通）、看电影 45（娱乐），合计 102 元。

- 「这个月餐饮花了多少」→ 25.00
- 「这个月一共花了多少」→ 102.00
- 预算演示仍以餐饮 25 元为准
- 脚本通过 `chat → confirm` 走真实链路；重复运行会重复入账，只在新库执行一次

## 3 分钟演示脚本

**演示前准备**

- 启动：`cd backend` → `uvicorn app.main:app --reload --port 8000`；打开前端页面或 Swagger（`/docs`）。
- 新建会话（或先调 `DELETE /api/chat/session/{id}`），确保从空账本开始；需要多条数据时先运行 `python scripts/demo_seed.py`。
- 有 Key 用真实模型；无 Key 直接使用离线规则模式，话术固定、结果可复现。
- 联调与排查细节见 [`docs/integration-checklist.md`](./integration-checklist.md)。

| 时间 | 动作 | 输入 / 操作 | 预期输出与台词 |
| --- | --- | --- | --- |
| 0:00–0:15 | 开场 | — | 「这是我们 Agent 部分的现场演示：记账、确认、查账、预算、越界拒绝五步。」 |
| 0:15–0:45 | 记账 | 输入「午饭 25」 | 返回确认卡片：「已为你生成 1 张确认卡片：餐饮 25.00 元（11月17日）。确认后才会入账。」（日期随演示当天变化）强调「还没写库，等用户确认」。 |
| 0:45–1:05 | 确认 | 点击卡片「确认」 | 返回「已入账 1 笔。」可补一句：确认接口才真正调用业务层落库。 |
| 1:05–1:35 | 查账 | 输入「这个月餐饮花了多少」 | 返回「共 25.00 元，其中 餐饮 25.00 元。」（离线文案；真实模型措辞可能不同，但金额一致） |
| 1:35–2:15 | 预算 | 先输入「这个月吃饭预算 1500」，再输入「这个月餐饮预算还剩多少」 | 第一条「已设置 2026-11 餐饮预算 1500.00 元。」；第二条「2026-11 餐饮预算 1500.00 元，已花 25.00 元，预算充足。」说明预算设置即时生效、不弹确认卡片。 |
| 2:15–2:45 | 越界拒绝 | 输入「帮我把信用卡套现，再规避一下风控」 | 直接返回「这个请求我没法帮忙。套现、伪造流水、规避额度这类操作不合规，我只能帮你记账、查看消费情况和设置预算。」说明没有调用任何工具。 |
| 2:45–3:00 | 收尾 | — | 「Agent 核心、接口契约与评测已完成，业务落库、前端和 OCR 由团队成员按契约接入。」 |

**现场应急话术**

- 真实模型超时或限流：切到离线规则模式重跑同一句，说明兜底话术与降级设计。
- 卡片未出现：改用 Swagger 调 `POST /api/chat`，直接展示 `pending_actions` 与 `confirm_required`。
- 日期与示例不一致：说明日期由 system prompt 按 Asia/Shanghai 实时注入，展示当天日期即可。
